API & provider setup

This is a starter integration, not an API key generator. You need your own provider account and credentials.

Order endpoint

POST /api/order
Authorization: Bearer <Supabase access token>
Content-Type: application/json

{"service":"PROVIDER_SERVICE_ID","link":"https://example.com/post","quantity":100}

The server validates service IDs and quantity limits, calculates charges from provider rates, reserves wallet funds atomically, stores order history, and refunds wallet funds if the provider rejects an order. Verify response formats before launch.

Required environment variables

SUPABASE_URL — your Supabase project URL

SUPABASE_ANON_KEY — public/anon key used for authentication

SUPABASE_SERVICE_ROLE_KEY — private server-only database key

ADMIN_PASSWORD — a new, strong unique admin password

ADMIN_SESSION_SECRET — random secret of at least 32 characters

SMM_PROVIDER_URL and SMM_PROVIDER_KEY — your real provider API details

Configure these as private environment variables in your host and redeploy. Never expose the service-role or provider keys in frontend code or public commits.

Database and manual deposits

Run the whole sql/schema.sql file in Supabase SQL Editor. Deposits are manual: the user submits a transaction ID and an admin independently verifies payment before approving. Automatic payment confirmation is not included.
